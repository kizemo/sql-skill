# 执行准确率 A/B 评测报告 · 2026-10-26

**问题**:`sql-skill` 的知识塞进 prompt 后,能不能真的提高 SQL 生成准确率?

**结论**:**在这个规模下没有可测量的增益。** 但这个"负结果"比一个假的正结果更有价值 —— 它澄清了 skill 的价值到底在哪。

---

## 1. 方法

| 项 | 值 |
|---|---|
| 题库 | civilian7 1090 题中的随机 12 题(`--seed 42` 固定,两轮同一批) |
| 模型 | MiniMax-M3.1-Flash(经 Anthropic 兼容中继) |
| 数据库 | civilian7 `ecommerce-playground.db`(32 张电商表) |
| 评分 | **执行准确率** —— 生成 SQL 与 reference SQL 在 SQLite 上的**结果集**逐行相同才算对(不比 SQL 文本) |
| 对照 | A 轮 `context=none`(只给 schema + 题目)<br>B 轮 `context=skill`(额外注入匹配到的 sql-skill 章节,≤4000 字符) |

命令:

```bash
python tools/eval_civilian7.py --mode claude-api --db <playground.db> \
  --api-sample 12 --seed 42 --context none
python tools/eval_civilian7.py --mode claude-api --db <playground.db> \
  --api-sample 12 --seed 42 --context skill
```

## 2. 结果

|---|---:|---:|---:|---:|
| A · context=none | 12 | 2 | **16.7%** | 0 |
| B · context=skill | 11 | 2 | **18.2%** | 1(超时) |

## 3. 解读 —— 三个必须说清楚的点

### 3.1 那 2 个百分点是**分母假象**,不是提升

`18.2% > 16.7%` 看起来像 skill 赢了,但:

- **0 题从 wrong 翻成 correct**
- 唯一的状态变化是 `a19-03`:`wrong → api_error`
- B 轮因为超时少算一题,**分母从 12 变成 11**,2/11 = 18.2% > 2/12 = 16.7%

**如果去掉那题超时,两轮都是 2/12 = 16.7%,完全打平。**

### 3.2 注入 skill 上下文**没帮上忙,还引入了超时**

`a19-03` 在 B 轮超时 —— skill 上下文让 prompt 变长(prefill 更久),**更容易撞超时**。

这是本次评测最实在的一个发现:**把 4000 字符知识原文塞进 prompt,是"用错方式"**。

### 3.3 sql-skill 的价值不在"塞进 prompt",在"路由到正确的章"

skill 的设计本来就是**渐进式披露**:

```
index 层(100 tok,每会话都付) ──► 路由:这题该读 ch08
        ↓ 按需
chapters/ch08-indexes-perf.md ──► 只读这一段
```

也就是说,agent 用 skill 的方式是**查目录 → 读对应章节 → 应用结论**,不是把知识灌进上下文。

而"能不能路由到正确的章节"这件事,**已经由另一个指标直接测了** —— 知识覆盖率:

```
python tools/eval_civilian7.py --mode skill-aware
# [OK] skill-aware: 100.0% coverage (1090/1090)
```

1090 题全部能定位到正确的章节,这是**路由能力**的直接测量,比 12 题的准确率 A/B 更可信、样本也大 90 倍。

## 4. 这份报告的边界

诚实地说,这次 A/B 有三个**已知不足**:

1. **样本太小**(12 题,其中 10 题 advanced)→ 统计功效低,任何差值都可能是噪声
2. **模型偏弱**(MiniMax-M3.1-Flash)→ 12 题里 10 题做不对,天花板效应严重,skill 的作用没机会体现
3. **API 不稳定** → 12 题里 1 题超时,直接影响分母

**因此本报告只支持一个结论:「在当前模型 + 当前样本下,注入 skill 原文没有可测量的准确率增益」。**

它**不支持**「skill 无用」这种结论 —— 那个结论需要更强的模型和更大的样本才能下。

## 5. 下一步(如果要把这个指标做实)

- [ ] 换强模型(`--model claude-sonnet-5` / `claude-opus-5-5`),样本 ≥100 题
- [ ] 分层抽样,保证 beginner/intermediate/advanced 各占 1/3(现在 advanced 占 10/12)
- [ ] 加 `context=chapter` 模式:只注入**匹配章节里最相关的 N 行**,而不是整章前 4000 字符
- [ ] 加 `context=cheatsheet` 模式:cheatsheet 是决策表,信息密度比章节原文高得多
- [ ] 记录每题 API 延迟,统计 skill 上下文的 token/延迟开销

## 6. 复现

```bash
# 数据与工具都在仓库里
python tools/eval_civilian7.py --mode skill-aware
python tools/eval_civilian7.py --mode baseline --db <playground.db> --sample 300
python tools/eval_civilian7.py --mode claude-api --db <playground.db> --api-sample 12 --seed 42 --context none
python tools/eval_civilian7.py --mode claude-api --db <playground.db> --api-sample 12 --seed 42 --context skill
```

底层 JSON 报告可用 `--out-json` 指定路径。
